# 条件成就

> 使用多个条件类型组合实现复杂判断逻辑的进阶成就。
> 通过多个 `conditions` 条目交叉组合，创建精细的触发规则。

---

## 设计思路

单条件成就是"玩家做了某件事"，但实际游戏中常需要更精确的判定：

1. **确认上下文**：玩家在哪里做的？在什么游戏模式下？装备了什么？
2. **多维度匹配**：例如"在地狱击杀烈焰人"——需要 entities + worlds + game_modes 三重判断
3. **防止作弊**：通过 game_modes 排除创造模式

**条件组合逻辑：** 多个条件条目之间是 **AND（与）** 关系——所有条件必须同时满足才计为一次有效操作。条件字段内的列表值是 **OR（或）** 关系。

---

## 完整示例 1：地狱探索者（worlds + entities + game_modes）

在地狱中击杀烈焰人。三重条件组合：正确的世界 + 正确的生物 + 正确的游戏模式。

```yaml
nether-explorer:
  type: KILL  # 触发类型：击杀实体时检测
  name: "&c地狱探索者"
  description:
    - "&7在地狱中击杀 &c50 &7只烈焰人"
  conditions:  # 条件列表：条目之间为 AND 关系
    - type: entities  # 条件：匹配被击杀的实体类型
      entities:
        - BLAZE  # 必须击杀烈焰人
    - type: worlds  # 条件：匹配所在世界
      worlds:
        - world_nether  # 必须在地狱世界中
    - type: game_modes  # 条件：匹配当前游戏模式
      game-modes:
        - SURVIVAL  # 必须在生存模式下
  tiers:
    1:
      required-amount: 50  # 三项条件同时满足 50 次即达标
      rewards:
        - type: points
          amount: 25
        - type: vault
          amount: 3000
        - type: broadcast
          message: "&c&l[成就] &f<player> &7在地狱击杀了 50 只烈焰人！"
```

## 完整示例 2：全副武装（has_equipped + entities）

穿着全套钻石装备击杀敌对生物。

```yaml
well-equipped:
  type: KILL  # 触发类型：击杀实体时检测
  name: "&b全副武装"
  description:
    - "&7穿着全套钻石装备击杀 &b100 &7只敌对生物"
  conditions:
    - type: entities  # 条件：匹配被击杀的实体
      entities:
        - ZOMBIE
        - SKELETON
        - SPIDER
    - type: has_equipped  # 条件：匹配玩家装备的物品
      items:  # 格式为 "槽位:物品ID"
        - "helmet:DIAMOND_HELMET"  # 头盔槽位
        - "chestplate:DIAMOND_CHESTPLATE"  # 胸甲槽位
        - "leggings:DIAMOND_LEGGINGS"  # 护腿槽位
        - "boots:DIAMOND_BOOTS"  # 靴子槽位
  tiers:
    1:
      required-amount: 100  # 穿着全套钻石装击杀 100 只达标
      rewards:
        - type: points
          amount: 30
        - type: vault
          amount: 5000
        - type: broadcast
          message: "&b&l[成就] &f<player> &7全副武装，所向披靡！"
```

## 完整示例 3：炼金术师（BREW + potion_types）

酿造指定类型的药水。

```yaml
alchemist:
  type: BREW  # 触发类型：酿造药水时检测
  name: "&d炼金术师"
  description:
    - "&7酿造 &d50 &7瓶迅捷药水"
  conditions:
    - type: potion_types  # 条件类型：匹配药水效果类型
      types:
        - SPEED  # 迅捷药水
  tiers:
    1:
      required-amount: 50  # 酿造 50 瓶迅捷药水达标
      rewards:
        - type: points
          amount: 15
        - type: vault
          amount: 1500
        - type: broadcast
          message: "&d&l[成就] &f<player> &7成为了一名炼金术师！"
```

## 完整示例 4：上勾拳！（DAMAGE + damage_causes + entities）

对敌对生物造成坠落伤害（将怪物打落悬崖/高空）。

```yaml
falcon-punch:
  type: DAMAGE  # 触发类型：造成伤害时检测
  name: "&e上勾拳！"
  description:
    - "&7用坠落伤害攻击 &e30 &7只敌对生物"
  conditions:
    - type: entities  # 条件：匹配受到伤害的实体
      entities:
        - ZOMBIE
        - SKELETON
        - SPIDER
        - CREEPER
    - type: damage_causes  # 条件：匹配伤害原因类型
      causes:
        - FALL  # 坠落伤害（如打落悬崖）
  tiers:
    1:
      required-amount: 30  # 造成 30 次坠落伤害达标
      rewards:
        - type: points
          amount: 20
        - type: vault
          amount: 2000
        - type: broadcast
          message: "&e&l[成就] &f<player> &7用上勾拳击飞了 30 只怪物！"
```

## 条件匹配逻辑总结

```yaml
conditions:
  - type: worlds           # AND: 必须在指定世界
    worlds:
      - world_nether
  - type: entities         # AND: 目标必须是这些实体之一
    entities:
      - BLAZE              # OR: 烈焰人
      - WITHER_SKELETON    # OR: 凋灵骷髅（同样满足）
  - type: game_modes       # AND: 游戏模式必须是这些之一
    game-modes:
      - SURVIVAL
# 所有条件字段全部满足 → +1 计数
# 任一条件不满足 → 事件被忽略
```

### 条件类型速查

| 条件类型 | 匹配字段 | 说明 |
|---------|---------|------|
| `items` | `items` | 匹配使用的/获得的物品 |
| `blocks` | `blocks` | 匹配破坏/放置的方块 |
| `entities` | `entities` | 匹配交互的实体 |
| `worlds` | `worlds` | 匹配所在世界 |
| `game_modes` | `game-modes` | 匹配游戏模式 |
| `has_equipped` | `items` | 匹配装备槽内容（格式: `"槽位:物品"`) |
| `has_item` | `items` | 匹配物品栏内容 |
| `has_held` | `items` | 匹配手持物品 |
| `potion_types` | `types` | 匹配药水效果类型 |
| `damage_causes` | `causes` | 匹配伤害原因类型 |
| `biomes` | `biomes` | 匹配生物群系 |
| `is_sneaking` | `value` | 是否潜行 |
| `is_sprinting` | `value` | 是否疾跑 |
| `is_flying` | `value` | 是否飞行 |
| `regions` | `regions` | 匹配 WorldGuard 区域 |
| `placeholder` | `placeholder`, `value`, `operator` | 匹配 PlaceholderAPI 占位符值 |

> **核心原则：条件条目间是 AND，条目内列表值是 OR。**
>
> 理解这个逻辑是配置复杂成就的关键。每个条件条目都是"过滤层"，层与层之间取交集，层内取并集。
