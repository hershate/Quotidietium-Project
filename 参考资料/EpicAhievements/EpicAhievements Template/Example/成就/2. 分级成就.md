# 分级成就

> 具有多个层级（tier）的成就，玩家可以逐级解锁，每级要求递增且奖励递增。
> 适合长期追踪的玩家生涯成就，让玩家有持续追求的目标。

---

## 设计思路

分级成就创造了一个**持续的进度系统**：
1. **渐进式难度**：从"简单入门"到"大师级"，让玩家始终有目标
2. **持续奖励感**：每完成一个层级就获得一次奖励，正反馈不断
3. **长期粘性**：最高层级的巨额需求让玩家长期活跃

**层级需求呈指数增长**（100 → 500 → 2000 → 5000 → 10000），而不是等差递增。
高层级自动包含低层级的计数（挖矿 10000 自动包含了挖矿 500 的进度）。

---

## 完整示例 1：采矿生涯（5 个层级）

追踪玩家破坏各类矿石的总数，5 个层级从学徒到传奇。

```yaml
master-miner:
  type: BREAK  # 触发类型：破坏方块时检测
  name: "&6采矿生涯"  # 成就显示名称（所有层级共用）
  description:
    - "&7开采各类矿石"
  conditions:
    - type: blocks  # 条件类型：匹配破坏的方块
      blocks:  # 支持的矿石类型列表
        - COAL_ORE
        - DEEPSLATE_COAL_ORE
        - IRON_ORE
        - DEEPSLATE_IRON_ORE
        - GOLD_ORE
        - DEEPSLATE_GOLD_ORE
        - REDSTONE_ORE
        - DEEPSLATE_REDSTONE_ORE
        - LAPIS_ORE
        - DEEPSLATE_LAPIS_ORE
        - COPPER_ORE
        - DEEPSLATE_COPPER_ORE
        - DIAMOND_ORE
        - DEEPSLATE_DIAMOND_ORE
        - EMERALD_ORE
        - DEEPSLATE_EMERALD_ORE
  tiers:
    1:  # 第一级：学徒（需要 100 次）
      required-amount: 100  # 总累积需求，非增量
      rewards:
        - type: points
          amount: 5
        - type: vault
          amount: 300
        - type: message
          message: "&7你成为了采矿学徒！"
    2:  # 第二级：专家（需要 500 次）
      required-amount: 500
      rewards:
        - type: points
          amount: 10
        - type: vault
          amount: 1000
        - type: broadcast  # 全服广播公告成就
          message: "&e&l[成就] &f<player> &7成为了采矿专家！"
    3:  # 第三级：大师（需要 2000 次）
      required-amount: 2000
      rewards:
        - type: points
          amount: 20
        - type: vault
          amount: 3000
        - type: broadcast
          message: "&b&l[成就] &f<player> &7成为了采矿大师！"
    4:  # 第四级：宗师（需要 5000 次）
      required-amount: 5000
      rewards:
        - type: points
          amount: 35
        - type: vault
          amount: 8000
        - type: broadcast
          message: "&d&l[成就] &f<player> &7成为了采矿宗师！"
    5:  # 第五级：传奇（需要 10000 次）
      required-amount: 10000
      rewards:
        - type: points
          amount: 50
        - type: vault
          amount: 20000
        - type: broadcast
          message: "&6&l[传奇] &f<player> &6成为了传奇矿工！"
```

## 完整示例 2：农耕之路（4 个层级）

追踪玩家收获各类农作物的总数。

```yaml
master-farmer:
  type: HARVEST  # 触发类型：收获作物时检测
  name: "&a农耕之路"  # 成就显示名称
  description:
    - "&7收获各类农作物"
  conditions:
    - type: blocks  # 条件类型：匹配收获的方块
      blocks:  # 支持的农作物类型
        - WHEAT
        - CARROTS
        - POTATOES
        - BEETROOTS
        - NETHER_WART
        - MELON
        - PUMPKIN
        - SUGAR_CANE
        - BAMBOO
        - CACTUS
  tiers:
    1:  # 农场新手（200 次）
      required-amount: 200
      rewards:
        - type: points
          amount: 5
        - type: vault
          amount: 200
        - type: message
          message: "&7你成为了农场新手！"
    2:  # 辛勤农夫（1000 次）
      required-amount: 1000
      rewards:
        - type: points
          amount: 10
        - type: vault
          amount: 800
        - type: broadcast
          message: "&e&l[成就] &f<player> &7成为了一名辛勤农夫！"
    3:  # 资深种植者（5000 次）
      required-amount: 5000
      rewards:
        - type: points
          amount: 20
        - type: vault
          amount: 3000
        - type: broadcast
          message: "&b&l[成就] &f<player> &7成为了资深种植者！"
    4:  # 丰收大师（15000 次）
      required-amount: 15000
      rewards:
        - type: points
          amount: 40
        - type: vault
          amount: 10000
        - type: broadcast
          message: "&6&l[传奇] &f<player> &6成为了丰收大师！"
```

## 关键概念总结

| 概念 | 说明 | 注意事项 |
|------|------|---------|
| `tiers` | 层级列表，按数字编号（1, 2, 3...） | 必须从 `1` 开始连续编号 |
| `required-amount` | 达成此层级所需的总完成数量 | **累积值**，不是增量值 |
| `rewards` | 该层级的奖励列表 | 高层级奖励应显著高于低层级 |

### 层级数量与需求设计参考

| 层级数 | 适用场景 | 需求递增模式 | 示例 |
|--------|---------|-------------|------|
| 3 层 | 短期活动、月度挑战 | 10 / 50 / 200 | 小型活动 |
| 4 层 | 生涯成就、职业路线 | 200 / 1000 / 5000 / 15000 | 农耕 |
| 5 层 | 核心玩法、长期养成 | 100 / 500 / 2000 / 5000 / 10000 | 采矿 |

> **核心原则：层级需求呈指数增长，奖励逐级提升，避免等差递增。**
>
> 每个层级**只包含** `required-amount` 和 `rewards`，不设置 `name` 或 `description`。成就的显示名称和描述由顶层 `name` 和 `description` 统一控制。
