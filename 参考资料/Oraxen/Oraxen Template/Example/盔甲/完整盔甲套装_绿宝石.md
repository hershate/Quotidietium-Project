# 完整盔甲套装 — 绿宝石 (Emerald)

> **适用版本**: Minecraft 1.21.2+ (组件方式)
> **设计理念**: 生命强化型坦克套装 -- 唯一同时提供 HP 加成和护甲值的套装
> **参考来源**: 项目 `Oraxen/items/armors.yml` 的 `emerald` 套装 (4件)
> **推荐阅读**: `参考资料/Oraxen/Oraxen Template/General/盔甲_组件_1.21.2+.md`

---

## 套装概览

绿宝石套装是生命值强化型坦克套装的范例。它在提供标准钻石级护甲的同时，每件还额外增加最大生命值 (MAX_HEALTH)，使穿戴者成为一个移动的血牛。

| 部位 | 物品 ID | 耐久度 | HP加成 | 护甲值 | 护甲韧性 | 槽位 |
|------|---------|:------:|:------:|:------:|:--------:|:----:|
| 头盔 | `emerald_helmet` | 437 | +2 (1心) | 3 | 2 | HEAD |
| 胸甲 | `emerald_chestplate` | 635 | +3 (1.5心) | 8 | 2 | CHEST |
| 护腿 | `emerald_leggings` | 595 | +3 (1.5心) | 6 | 2 | LEGS |
| 靴子 | `emerald_boots` | 516 | +2 (1心) | 3 | 2 | FEET |
| **合计** | | | **+10 (5心)** | **20** | **8** | |

> **原版参考**: 钻石套总护甲值 = 20 (3+8+6+3), 总韧性 = 8 (2+2+2+2)。绿宝石套装的护甲值与钻石套持平，护甲韧性与钻石套持平，额外提供 5 颗心的生命上限提升。

## 需要的纹理文件 (共 6 个)

所有纹理放入 `~/textures/default/armors/` 目录:

```
资源包纹理:
├── textures/default/armors/
│   ├── emerald_armor_layer_1.png    ← [必须] 盔甲层 1 (64x32 像素 @ 分辨率 16)
│   ├── emerald_armor_layer_2.png    ← [必须] 盔甲层 2 (64x32 像素 @ 分辨率 16)
│   ├── emerald_helmet.png           ← [必须] 头盔物品图标
│   ├── emerald_chestplate.png       ← [必须] 胸甲物品图标
│   ├── emerald_leggings.png         ← [必须] 护腿物品图标
│   └── emerald_boots.png            ← [必须] 靴子物品图标
```

> **命名强制要求**: 盔甲层纹理必须以 `<盔甲名>_armor_layer_X.png` 命名。物品图标纹理必须以 `<盔甲名>_<部位>.png` 命名。Oraxen 根据文件名中的 `armor_layer_1` / `armor_layer_2` 自动区分第一层和第二层纹理。

## 完整 YAML 配置 (4件套)

```yaml
# =============================================================================
# 绿宝石盔甲套装 — 组件方式 (Minecraft 1.21.2+)
#
# 设计理念: 生命强化型坦克套装
#   - 护甲值 = 原版钻石套标准 (头盔3/胸甲8/护腿6/靴子3)
#   - 护甲韧性 = 原版钻石套标准 (每件2)
#   - 额外HP = +10 点 (合 5 颗心), 分配逻辑: 头+1心 / 胸+1.5心 / 腿+1.5心 / 靴+1心
#   - 耐久度 = 原版钻石套的近似值
#
# 使用方法: 全局替换 "emerald" 为你的盔甲名称, "Emerald" 为显示名称
# =============================================================================

# ====================================================================
# 1. 绿宝石头盔 — emerald_helmet
# ====================================================================
#
# 【物品 ID 命名规则】
#   必须遵循 <盔甲名>_helmet 格式。Oraxen 根据此后缀自动识别为头盔类物品，
#   并分配 HEAD 槽位。如果你省略 Components.equippable 块，Oraxen 会自动推断
#   slot: HEAD 和 model: oraxen:<盔甲名>。手动指定可确保精确控制。
#
emerald_helmet:

  # ---- [必须] 显示名称 ----
  # MiniMessage 格式: <gradient:#起始色:#结束色>文本
  # 渐变色在 1.21.2+ 中原生支持，无需额外插件。
  # #89E59D = 柔和的薄荷绿, #37C6BA = 蓝绿色
  # 这种双色渐变给物品名称增添高级感和层次感。
  displayname: <gradient:#89E59D:#37C6BA>Emerald Helmet

  # ---- [必须] 基础材质 ----
  # material 决定物品栏中的基础物品类型。
  # PAPER 材质本身没有任何盔甲属性——我们通过下文的 AttributeModifiers 手动添加。
  #
  # 为什么用 PAPER 而不是 DIAMOND_HELMET？
  #   1. PAPER 不携带任何原版盔甲属性，所有数值由你精确控制
  #   2. 如果用 DIAMOND_HELMET，它会自带钻石防御值 (3 armor + 2 toughness)，
  #      与你手动添加的属性叠加，可能导致数值异常
  #   3. PAPER 没有耐久度系统干扰——通过 durability 组件精确指定
  #   4. PAPER 材质外观完全由 Pack.textures 中的自定义纹理决定
  #
  material: PAPER

  # ---- [可选] 物品描述 (Lore) ----
  # MiniMessage 颜色代码:
  #   <#6f737d> = 柔和的灰色 (用于装饰符号 »)
  #   <#D5D6D8> = 明亮的浅灰色 (用于描述文本)
  #   <glyph:heart> = 自定义字形 (如果配置了 heart 字形, 显示为爱心图标)
  #
  # 「Gives 1 extra <glyph:heart>」 — 告知玩家这件装备提供 +1 心生命上限
  lore:
    - <#6f737d>» <#D5D6D8>Gives 1 extra <glyph:heart>

  # ---- [必须] 物品组件 ----
  # 从 Minecraft 1.21.2 开始，物品属性统一由 Components 块管理。
  # 这与旧版的 AttributeModifiers 顶层键是两种不同的配置路径——
  # Components 是原版 data component 系统, AttributeModifiers 是 Oraxen 的兼容层。
  # 本项目使用的是顶层 AttributeModifiers 方式（见下文），
  # Components 块中只放置无法通过顶层键表达的组件（如 max_stack_size, durability, equippable）。
  #
  Components:

    # ---- max_stack_size: 最大堆叠数量 ----
    # 盔甲类物品必须设为 1，因为玩家同一槽位只能穿一件。
    # 设为 1 也防止意外堆叠导致属性叠加 bug。
    # 原版所有盔甲 (钻石/铁/锁链/皮革/下界合金) 的 max_stack_size 均为 1。
    max_stack_size: 1

    # ---- durability: 耐久度组件 ----
    # value: 物品的最大耐久度。
    #   原版钻石头盔耐久 = 363, 此处设为 437 (约 1.2 倍钻石耐久)。
    #   不同部位的耐久度应遵循以下比例 (参考原版钻石套):
    #     头盔 : 胸甲 : 护腿 : 靴子
    #     363 :  528 :  495 :  429  (原版钻石)
    #   本套装近似维持此比例, 整体略高于钻石套。
    #
    # damage_entity_hit: true
    #   含义: 当玩家使用此物品**直接攻击**实体时, 物品消耗 1 点耐久。
    #   - true  → 攻击也会消耗耐久 (与武器逻辑一致)
    #   - false → 攻击不消耗耐久 (仅被攻击时消耗, 由原版盔甲系统自动处理)
    #   原版盔甲在受到伤害时会自动消耗耐久度，不需要此设置。
    #   此设置仅控制"用盔甲打人"时的耐久消耗。
    #
    durability:
      value: 437
      damage_entity_hit: true

    # ---- equippable: 可装备组件 ----
    # Minecraft 1.21.2+ 引入的原版组件，用于定义物品可以装备到哪个盔甲槽位，
    # 以及装备后使用哪个模型渲染在玩家身上。
    #
    # slot: 装备槽位
    #   可选值: HEAD / CHEST / LEGS / FEET
    #   头盔 → HEAD    胸甲 → CHEST    护腿 → LEGS    靴子 → FEET
    #
    # model: 装备后的玩家模型
    #   命名规则: oraxen:<盔甲名> (不含 _helmet 等部位后缀)
    #   例如: emerald_helmet  → model: oraxen:emerald
    #         emerald_boots   → model: oraxen:emerald
    #         ruby_chestplate → model: oraxen:ruby
    #
    #   错误示例:
    #     model: oraxen:emerald_helmet  ← 不要包含 _helmet 后缀!
    #     model: minecraft:diamond      ← 不要使用 minecraft 命名空间!
    #
    #   Oraxen 自动映射规则:
    #     所有 4 件套使用同一个 model 名 (如 oraxen:emerald)，
    #     Oraxen 内部根据 slot 值和物品 ID 后缀自动选择
    #     emerald_armor_layer_1.png 或 emerald_armor_layer_2.png 来渲染。
    #
    equippable:
      slot: HEAD
      model: oraxen:emerald

  # ---- [必须] 属性修改器 ----
  # AttributeModifiers 为物品添加 Minecraft 属性修改。
  # 每个修改器由 4 个字段组成:
  #   attribute: 属性名 (大写, 下划线分隔)
  #   amount:    修改数值 (正数=增加, 负数=减少)
  #   operation: 运算方式 (0/1/2 — 见下方详解)
  #   slot:      生效槽位 (HEAD/CHEST/LEGS/FEET — 只有装备在指定槽位时才生效)
  #
  # 【operation 详解 — 三种运算方式】
  #
  #   operation: 0 (ADD_NUMBER / 加法)
  #     将 amount 直接加到基础值。
  #     公式: 最终值 = 基础值 + amount
  #     示例: 玩家基础生命 20, amount=2, operation=0 → 最终生命 = 22 (即 +1 心)
  #     用途: 最常用的方式, 用于给予固定的属性加成
  #
  #   operation: 1 (ADD_SCALAR / 百分比加法)
  #     将 amount 作为百分比加到基础值上。
  #     公式: 最终值 = 基础值 + (基础值 x amount)
  #     示例: 玩家基础生命 20, amount=0.25, operation=1 → 最终生命 = 20 + (20 x 0.25) = 25
  #     注意: amount=1 表示 +100%, amount=0.5 表示 +50%
  #     用途: 适合需要"按比例增强"的场景——基础属性越高, 加成越多
  #
  #   operation: 2 (MULTIPLY_BASE / 乘法)
  #     将 amount 作为倍率乘以基础值。
  #     公式: 最终值 = 基础值 x (1 + amount)
  #     示例: 玩家基础生命 20, amount=0.5, operation=2 → 最终生命 = 20 x 1.5 = 30
  #     注意: 此运算在 operation 0 和 1 之后执行, 会受到前两者结果的叠加影响
  #     用途: 适合需要"全局倍率"的场景——在所有加法加成后再做乘法
  #
  #   【运算叠加顺序】
  #     多个修改器同时存在时, Minecraft 按照 operation 值从小到大依次计算:
  #       先计算所有 operation: 0 (加法)
  #       再计算所有 operation: 1 (百分比加法)
  #       最后计算所有 operation: 2 (乘法)
  #     这意味着 operation:2 的修改器会在前两者结果的基础上进一步放大。
  #
  AttributeModifiers:

    # --- MAX_HEALTH: 最大生命值 ---
    # amount: 2 = +1 颗心 (Minecraft 中 1 点生命 = 半颗心)
    # 头盔提供 +1 心的生命上限提升 —— 头盔位最"轻", 加成适中
    - attribute: MAX_HEALTH
      amount: 2
      operation: 0          # 直接加法: 玩家基础生命 20 → 22
      slot: HEAD

    # --- ARMOR: 护甲值 ---
    # amount: 3 = 原版钻石头盔的标准护甲值
    #
    # 【原版护甲值体系参考】
    #   部位    | 皮革 | 锁链 | 铁 | 钻石 | 下界合金
    #   头盔    |   1  |   2  |  2 |   3  |    3
    #   胸甲    |   3  |   5  |  6 |   8  |    8
    #   护腿    |   2  |   4  |  5 |   6  |    6
    #   靴子    |   1  |   1  |  2 |   3  |    3
    #   全套合计 |   7  |  12  | 15 |  20  |   20
    #
    #   ARMOR 值影响伤害减免百分比。原版公式: 减免% = armor x 4%
    #   满 20 护甲值 = 80% 伤害减免 (原版封顶)
    #
    - attribute: ARMOR
      amount: 3
      operation: 0          # 直接加法: 基础护甲 + 3
      slot: HEAD

    # --- ARMOR_TOUGHNESS: 护甲韧性 ---
    # amount: 2 = 原版钻石的韧性标准
    #
    # 护甲韧性的作用:
    #   原版钻石套 (韧性=8, 即每件2) 在受到高伤害攻击时, 护甲值的减免效果衰减更少。
    #   简单理解: 韧性越高, 护甲在面对高伤时越"硬"。
    #   公式涉及: 伤害 / (韧性 + 8), 韧性越大, 高伤穿透越少。
    #
    # 原版韧性参考值:
    #   皮革/锁链/铁: 韧性 = 0
    #   钻石: 韧性 = 2 (每件)
    #   下界合金: 韧性 = 3 (每件)
    #
    - attribute: ARMOR_TOUGHNESS
      amount: 2
      operation: 0
      slot: HEAD

  # ---- [必须] 资源包 (Pack) 配置 ----
  # Pack 块控制物品在资源包中的模型生成。
  #
  # generate_model: true
  #   Oraxen 自动生成物品模型 JSON 文件。对于大多数自定义物品,
  #   应该设为 true。只有当你有手工制作的 .json 模型时才设为 false。
  #
  # parent_model: "item/generated"
  #   使用 Minecraft 的 "generated" 父模型。这是标准 2D 贴图物品的父模型，
  #   适合物品栏/手中显示。不要使用 "item/handheld" 否则贴图会被拉伸。
  #
  # textures:
  #   纹理路径列表。这里指定的是**物品栏图标**纹理 (不是穿戴纹理!)。
  #   路径指向 ~/textures/default/armors/emerald_helmet.png
  #   实际的文件需要放在资源包的 textures/default/armors/ 目录下。
  #
  #   物品图标纹理 vs 盔甲层纹理:
  #     - 物品图标: 在 Pack.textures 中配置, 影响物品栏/手中的外观
  #     - 盔甲层纹理: 命名为 emerald_armor_layer_1.png / _2.png,
  #       由 Oraxen 根据 equippable 组件的 slot 和 model 自动加载
  #     - 这两套纹理是完全独立的文件
  #
  Pack:
    generate_model: true
    parent_model: item/generated
    textures:
      - default/armors/emerald_helmet
```

## 套装的数值设计逻辑

### 护甲值分配原则 (原版钻石套标准)

```
部位     护甲值    占比    说明
头盔       3      15%    最小的防护区域
胸甲       8      40%    最大的防护区域, 承受最多攻击
护腿       6      30%    第二大的防护区域
靴子       3      15%    最小的防护区域
────────────────────────────────
合计      20     100%    原版满护甲减免 (80% 减伤)
```

### HP 加成分配 (独特设计)

```
部位     HP加成    心数    说明
头盔      +2       +1心   与靴子对称, 最小区域 = 最小加成
胸甲      +3     +1.5心   最大区域 = 最大加成
护腿      +3     +1.5心   第二大区域 = 大加成
靴子      +2       +1心   与头盔对称, 最小区域 = 最小加成
────────────────────────────────
合计     +10       +5心   总计 5 颗额外心的生命上限
```

> **设计启示**: 如果你要创建自己的套装, 可以参考此分配逻辑。护甲值建议遵循原版钻石套标准 (20点合计), HP 加成可以根据套装定位灵活调整——坦克套装加 HP, 敏捷套装可换用 MOVEMENT_SPEED 属性。

### 耐久度设计

绿宝石套装的耐久度略高于原版钻石套 (约 1.2 倍), 但远低于黑曜石套装 (10倍)。这体现了"中等强化"的设计定位——比钻石好一些, 但不会破坏平衡。

## 常见问题

**Q: 为什么不用 DIAMOND_HELMET 作为材质而是 PAPER?**
A: 使用 PAPER 让你完全掌控物品的每一个属性。如果用 DIAMOND_HELMET, 它会自带 3 armor + 2 toughness + 原版耐久度——这些会与你手动添加的属性叠加。PAPER 是一张白纸, 所有数值由你精确控制。

**Q: 为什么 4 件套的 model 都是 `oraxen:emerald` 而不是 `oraxen:emerald_helmet`?**
A: Oraxen 使用盔甲名 (不含部位后缀) 来匹配盔甲层纹理 (`emerald_armor_layer_1.png` / `_2.png`)。4 件套使用同一个 model 名, Oraxen 内部根据 slot 值决定渲染哪一层纹理。

**Q: 如果我想创建一个只有护甲没有 HP 加成的套装?**
A: 参考本目录下的 `完整盔甲套装_黑曜石.md` 或 `完整盔甲套装_红宝石.md` ——它们只有 ARMOR 和 ARMOR_TOUGHNESS 属性, 不包含 MAX_HEALTH。
