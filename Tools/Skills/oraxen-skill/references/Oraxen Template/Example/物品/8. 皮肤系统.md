# 皮肤系统

> Oraxen 皮肤系统允许玩家改变物品的外观纹理，而保留物品的所有属性和功能。
> 涉及两个角色：**皮肤接收方**（skinnable）和**皮肤消耗方**（skin）。

---

## 核心概念

皮肤系统是一个"换装"系统，类比：

```
skinnable 物品 = 一个人（可以被换不同的衣服）
skin 物品     = 一件衣服（右键使用，改变那个人的外观）
```

工作流程：
1. 玩家拥有一个 `skinnable` 物品（如钻石剑——可换肤的剑）
2. 玩家获得一个 `skin` 物品（如"SKIN: Great Sword"——一个皮肤消耗品）
3. 玩家**右键将 skin 物品拖动到 skinnable 物品上**（在物品栏中操作）
4. skinnable 物品的外观变成 skin 物品定义的纹理/模型
5. 所有属性（伤害、耐久、附魔、机制）保持不变——只有外观变了

---

## 1. skinnable 物品 -- 皮肤接收方

> 可以被皮肤改变外观的基础物品。

```yaml
# =============================================================================
# 可换肤的钻石剑 - skinnable 机制
# 这是一个普通的钻石剑，但它的外观可以被 skin 物品改变
# =============================================================================
diamond_sword:
  # --- 注意：这里没有 displayname——
  #     因为这个物品使用的是原版钻石剑名称
  #     你当然可以添加自定义 displayname
  # ---

  # --- 基础材质 ---
  # DIAMOND_SWORD: 这是一把钻石剑，拥有钻石剑的所有属性
  material: DIAMOND_SWORD

  # =========================================================================
  # Mechanics.skinnable —— 标记此物品可被皮肤改变外观
  #
  # 空花括号 {} = 使用默认配置
  # 这意味着：
  #   - 物品可以被任何 skin 物品改变外观
  #   - 没有额外的限制条件
  # =========================================================================
  Mechanics:
    skinnable: {}                    # 空配置 = 允许换肤
```

### skinnable 的高级用法

```yaml
# =============================================================================
# 高级 skinnable 物品 - 带限制条件的换肤
# 实际上大多数情况下 skinnable: {} 就够了
# 这里展示可能的扩展
# =============================================================================
# restricted_skinnable_sword:
#   displayname: "<#D5D6D8>可换肤的秘银剑"
#   material: DIAMOND_SWORD
#   Mechanics:
#     skinnable: {}
#   # 你可以同时拥有其他机制:
#     durability:
#       value: 2000
#     lifeleech:
#       amount: 1
#   # 皮肤只改变外观，不影响这些机制
```

## 2. skin 物品 -- 皮肤消耗方

> 右键使用，改变 skinnable 物品的外观。

```yaml
# =============================================================================
# 巨剑皮肤 - skin 机制
# 命名惯例: 在物品名称中包含 "SKIN:" 前缀，方便玩家识别这是皮肤物品
# =============================================================================
great_sword:
  # --- 显示名称 ---
  # 命名惯例：
  #   '<#D5D6D8><bold>SKIN: <gradient:...>皮肤名称'
  #
  # 为什么用 "SKIN:" 前缀？
  #   - 玩家一眼就能认出这是皮肤物品（不是真正的武器）
  #   - 在物品栏中快速区分"皮肤消耗品"和"可换肤物品"
  #   - 这是一个社区惯例，不是 Oraxen 强制要求
  #
  # 单引号包裹整个字符串：因为内容包含冒号 : 和条件格式
  # MiniMessage 中 : 有时需要引号保护
  displayname: '<#D5D6D8><bold>SKIN: <gradient:#3685EC:#72C1E4>巨剑'
  # 英文参考: SKIN: Great Sword

  # --- 基础材质 ---
  # DIAMOND_SWORD: 因为皮肤要应用到钻石剑上
  # 材质必须与目标 skinnable 物品一致（或兼容）
  material: DIAMOND_SWORD

  # =========================================================================
  # 外观 - 显示皮肤模型的预览
  # 这里使用 3D 模型，让玩家在物品栏中预览皮肤的外观
  # =========================================================================
  Pack:
    generate_model: false
    model: default/great_sword         # 皮肤 3D 模型

  Mechanics:
    # =========================================================================
    # skin 机制 —— 将此物品标记为"皮肤消耗品"
    #
    # consume: 使用后是否消耗
    #   true = 一次性使用（用完消失）
    #   false = 可以重复使用（保留皮肤物品）
    #
    # 为什么大多数皮肤设 consume: true？
    #   - 皮肤通常是"稀有/珍贵"的收藏品
    #   - 消耗后消失增加稀有感和价值
    #   - 防止玩家无限制地在多个物品间切换皮肤
    #
    # 什么时候设 consume: false？
    #   - 如果皮肤是解锁型（如"赛季奖励"——永久拥有）
    #   - 但这种情况下，通常用权限系统而非皮肤系统
    # =========================================================================
    skin:
      consume: true                    # 使用一次后消失
```

### 更多皮肤示例

```yaml
# =============================================================================
# 骨剑皮肤
# =============================================================================
bone_sword:
  displayname: '<#D5D6D8><bold>SKIN: <gradient:#89E59D:#37C6BA>骨剑'
  # 英文参考: SKIN: Bone Sword
  material: DIAMOND_SWORD
  Pack:
    generate_model: false
    model: default/bone_sword
  Mechanics:
    skin:
      consume: true

# =============================================================================
# 木剑皮肤
# =============================================================================
wood_sword:
  displayname: '<#D5D6D8><bold>SKIN: <gradient:#F06966:#FAD6A6>木剑'
  # 英文参考: SKIN: Wood Sword
  material: DIAMOND_SWORD
  Pack:
    generate_model: false
    model: default/wood_sword
  Mechanics:
    skin:
      consume: true
```

## 3. 完整工作流演示

以下是玩家使用皮肤的典型流程：

```
步骤 1: 玩家拥有物品
  ┌──────────────────────────────┐
  │ 物品栏中:                     │
  │  [钻石剑]  <- skinnable 物品  │
  │  [SKIN: 巨剑] <- skin 物品    │
  └──────────────────────────────┘

步骤 2: 拖动应用
  玩家在物品栏中右键拖动 [SKIN: 巨剑] 到 [钻石剑] 上

步骤 3: 消耗与应用
  ┌──────────────────────────────┐
  │ [SKIN: 巨剑] disappears       │  ← consume: true，消耗消失
  │ [钻石剑] 外观变为巨剑的 3D 模型│  ← 外观替换
  │ 但所有属性仍是钻石剑的属性     │  ← 属性保留
  └──────────────────────────────┘

步骤 4: 结果
  玩家现在有一把"看起来像巨剑的钻石剑"
  - 伤害、攻速、耐久、附魔 → 全部不变
  - 外观模型 → 变成巨剑的模型
  - 如果巨剑皮肤定义了不同的纹理路径 → 纹理也变更
```

## 4. 皮肤系统与其他机制的配合

皮肤系统与其他 Oraxen 机制完全兼容。换肤只改变 `CustomModelData` 和纹理引用，不影响物品的其他数据：

```yaml
# =============================================================================
# 可换肤的吸血剑 - 皮肤 + 战斗机制共存
# =============================================================================
# skinnable_vampire_sword:
#   displayname: "<gradient:#FA7CBB:#F14658>可换肤的吸血剑"
#   material: DIAMOND_SWORD
#   Pack:
#     generate_model: true
#     parent_model: item/handheld
#     textures:
#       - default/vampire_sword.png    # 默认外观
#   Mechanics:
#     skinnable: {}                    # 可换肤（可以用 skin 物品改变外观）
#     lifeleech:                       # 吸血机制（换肤后仍有效）
#       amount: 2
#     bleeding:                        # 流血机制（换肤后仍有效）
#       chance: 0.3
#       duration: 100
#       damage_per_interval: 0.5
#       interval: 20
#   Components:
#     durability: 500
#   # 换肤后：外观可以变，但吸血+流血+耐久度全部保留
```

## 5. skin 物品命名惯例详解

```yaml
# 推荐的命名模板（三种级别）
#
# 级别 1: 基础皮肤（白色文字）
#   '<#D5D6D8><bold>SKIN: <颜色>皮肤名'
#
# 级别 2: 稀有皮肤（渐变文字）
#   '<#D5D6D8><bold>SKIN: <gradient:#颜色1:#颜色2>皮肤名'
#
# 级别 3: 传说皮肤（带 lore）
#   displayname: '<#D5D6D8><bold>SKIN: <gradient:#颜色1:#颜色2>皮肤名'
#   lore:
#     - '<#6f737d>» <#D5D6D8>限定皮肤'
```

### 为什么用 SKIN: 前缀？

1. **视觉识别**：在物品栏中快速区分（哪些是消耗品皮肤，哪些是可换肤的基础物品）
2. **排序方便**：所有皮肤物品按字母排序时会集中在一起
3. **社区惯例**：Oraxen 社区的广泛实践，新玩家一看就懂
4. **不是强制要求**：你可以用其他命名方式，但 SKIN: 前缀是最清晰的

## 6. consume: true vs false 的应用场景

| 场景 | consume | 理由 |
|------|:---:|------|
| 一次性皮肤箱 | `true` | 打开箱子获得皮肤，使用后消失 |
| 活动奖励皮肤 | `true` | 稀有物品，消费后增加收藏价值 |
| 商店出售的皮肤 | `true` | 经济流通——玩家需要不断购买 |
| 永久解锁皮肤 | `false` | 如VIP特权皮肤，使用后不消失 |
| 赛季通行证奖励 | `true` | 通常是一次性奖励 |
| 默认皮肤（用于切换回原样） | `false` | 可以反复使用 |

## 7. 文件放置与纹理管理

当皮肤改变 skinnable 物品的外观时，改变的模型和纹理路径由 skin 物品的 Pack 部分定义：

```
skin 物品的模型: plugins/Oraxen/pack/models/default/great_sword.json
skin 物品的纹理: 嵌入在 JSON 模型文件中（通常由 Blockbench 管理）

玩家换肤后的物品会使用 skin 物品的 CustomModelData 对应的模型
```

> **关键理解：** skin 物品本身有一个模型预览（在物品栏中显示），换肤后 skinnable 物品会获得相同的模型引用。不需要为每个皮肤组合创建单独的纹理文件——皮肤系统复用 skin 物品的模型定义。

## 8. 常见问题排查

| 问题 | 可能原因 | 解决 |
|------|---------|------|
| 拖动皮肤没反应 | skinnable 物品没有 `skinnable: {}` 机制 | 检查基础物品配置 |
| 换肤后外观没变 | skin 物品模型文件不存在 | 检查 `models/` 目录 |
| 换肤后属性变了 | 可能用了不同 material 的物品作为皮肤目标 | skin 物品的 material 无关紧要；确保 skinnable 物品的 material 正确 |
| 皮肤消耗后找不回来 | `consume: true`，一次性的 | 设计上就是如此——确保玩家理解 |
| 多个皮肤物品混淆 | 命名不规范 | 使用 SKIN: 前缀统一标识 |
