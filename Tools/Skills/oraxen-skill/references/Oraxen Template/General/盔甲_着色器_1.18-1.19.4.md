## 方法概述

着色器方式是 Oraxen 最早实现的盔甲方案，利用了 Minecraft 原版的染色皮革盔甲系统和一个自定义着色器。

### 工作原理

1. 以 **LEATHER (皮革)** 盔甲为基础材质
2. 通过**自定义着色器**拦截皮革盔甲的颜色渲染，将其替换为自定义纹理
3. 盔甲在物品栏和手中显示正常纹理 (物品图标)
4. 盔甲穿戴在身体上时，着色器将皮革的染色层替换为你的 `armor_layer_1/2.png` 纹理

### 核心限制

着色器方式有最多的限制 — 这些是方法本身的固有限制，无法绕过:

| 限制 | 说明 | 严重程度 |
|------|------|:--------:|
| 基础材质仅限皮革 | 无法使用钻石、铁等材质 | 高 |
| 原版客户端纹理位深必须为 32 位 | 非 32 位 → 黑像素 | 高 |
| Optifine/Iris 着色器冲突 | 需要额外步骤修复 | 中 |
| 盔甲分辨率统一 | 所有着色器盔甲共享同一分辨率 | 低 |
| 无法使用原版纹饰 | 与纹饰系统不兼容 | 低 |

## 着色器兼容性

### 问题说明

Minecraft 的原版内置着色器与 Optifine / Iris 等模组提供的着色器存在**冲突**: Optifine/Iris 会重写渲染管线, 导致 Oraxen 用于替换盔甲纹理的自定义着色器失效。

### 解决方案

| 着色器加载器 | 解决方案 | 需要额外操作 |
|-------------|----------|:------------:|
| **无着色器 (原版)** | 原生支持 | 无 |
| **Optifine** | Oraxen 自动生成 CIT 纹理 | 无 — 全自动 |
| **Iris** | Oraxen 生成 CIT, 但需要 CIT Resewn | **安装 [CIT Resewn](https://modrinth.com/mod/cit-resewn)** |
| **Canvas** | 不兼容 | 建议更换着色器加载器 |
| **Sodium (无 Iris)** | 原生支持 (不影响着色器) | 无 |

### 关键注意

> 对于 **Optifine**: Oraxen 会自动为每个盔甲物品生成 CIT 属性文件 (`*.properties`), 放置在资源包中。
> 对于 **Iris**: Iris 不内置 CIT 支持。Oraxen 生成的 CIT 文件需要 [CIT Resewn](https://modrinth.com/mod/cit-resewn) 模组来读取。**这是一个常见的配置遗漏点。**

## 命名规范

### 物品 ID 命名

> **强制要求** — 与其他盔甲类型相同。

```
<盔甲名>_<部位类型>

部位类型 (必须精确匹配):
  _helmet      → 头盔
  _chestplate  → 胸甲
  _leggings    → 护腿
  _boots       → 靴子
```

**规则**: 部位类型必须是英文原版物品 ID 后缀。Oraxen 根据此后缀识别盔甲部位并分配正确的着色器行为。

### 纹理文件命名

> **强制要求** — 盔甲层纹理必须包含 `armor_layer_X` 并在文件名中体现盔甲名称前缀。

```
<盔甲名>_armor_layer_1.png    → 第一层 (上身躯干、头盔、靴子)
<盔甲名>_armor_layer_2.png    → 第二层 (护腿、以及上身/头盔的覆盖)
<盔甲名>_armor_layer_1_e.png  → [可选] 第一层发光贴图
<盔甲名>_armor_layer_2_e.png  → [可选] 第二层发光贴图
```

## 纹理格式与严格要求

### 分辨率

由 `settings.yml` 中的 `CustomArmor.armor_resolution` 控制:

```yaml
# settings.yml
CustomArmor:
  armor_type: SHADER            # [必须] 设为 SHADER
  armor_resolution: 16          # [可选] 默认 16
```

| armor_resolution | 纹理尺寸 (宽x高) | 说明 |
|:-----------------:|:-----------------|------|
| 16 (默认)         | 64 x 32           | 标准 Minecraft 分辨率 |
| 24                | 96 x 48           | 1.5x 分辨率 |
| 32                | 128 x 64          | 2x 高分辨率 |
| 64                | 256 x 128         | 4x 超高清 |
| 128               | 512 x 256         | 8x (性能影响大) |

**公式**: 宽度 = resolution x 4, 高度 = resolution x 2

**关键**: 所有使用着色器方式的盔甲共享同一个 `armor_resolution`。不能某些用 16、某些用 32。

### 位深 (Bit Depth) — 极其重要

> **这是着色器方式最容易出错的地方。不遵守此规则会导致纹理显示为黑色像素。**

| 项目 | 要求 |
|------|------|
| 位深 | **必须为 32 位** (RGBA, 每通道 8 位) |
| 透明通道 | 必须包含 Alpha 通道 |
| 其他位深 (24位/8位) | **会导致原版客户端所有盔甲纹理显示黑色** |
| Optifine/Iris 影响 | 位深不正确时，Optifine/Iris 版本可能正常，但原版全黑 |

**检查方式**:
- 在 Photoshop 中: 图像 → 模式 → RGB 颜色 + 8 位/通道 (结果是 32 位)
- 在 GIMP 中: 图像 → 模式 → RGB
- 确保保存为 PNG-24 (带透明) 或 PNG-32

**为什么**: Oraxen 的着色器使用像素的透明度值来决定是否用自定义纹理替换该像素。如果位深不足，透明通道信息丢失，着色器将拒绝替换，显示为 Minecraft 默认的黑色。

### 物品图标纹理

物品栏图标的纹理路径在 `Pack.textures` 中配置。与着色器方式的特殊性无关 — 这是标准的 Oraxen 资源配置。

```yaml
Pack:
  generate_model: true
  parent_model: "item/generated"
  textures:
    - default/armors/ruby_helmet      # 第一次指定: 物品栏 + 手中
    - default/armors/ruby_helmet      # [必须重复] 着色器内部引用
```

与纹饰方式类似，着色器方式通常也要求纹理路径指定两次。

## 完整配置模板 (4件套)

以下是一套完整的 4 件盔甲配置, 适用于着色器方式 (Minecraft 1.18-1.19.4)。

```yaml
# =============================================================================
# 红宝石盔甲套装 — 着色器方式 (Minecraft 1.18-1.19.4)
# 使用方法: 全局替换 "ruby" 为你的盔甲名称, "Ruby" 为显示名称
#
# 重要前提:
#   1. settings.yml: CustomArmor.armor_type: SHADER
#   2. 所有纹理必须是 32 位 PNG
#   3. 盔甲层纹理必须命名为 <盔甲名>_armor_layer_1.png 和 _2.png
# =============================================================================

# ============================
# 1. 头盔
# ============================
ruby_helmet:
  # ---- [必须] 显示名称 ----
  displayname: "<gradient:#FA7CBB:#F14658>Ruby Helmet"

  # ---- [必须] 基础材质 ----
  # 着色器方式强制使用皮革盔甲。无法更改!
  # 要获得实际的盔甲防御值, 请配合 AttributeModifiers 组件使用。
  material: LEATHER_HELMET

  # ---- [必须] 资源包配置 ----
  # 纹理路径需要指定两次
  Pack:
    generate_model: true
    parent_model: "item/generated"
    textures:
      - default/armors/ruby_helmet      # 物品图标纹理
      - default/armors/ruby_helmet      # [必须重复] 着色器渲染引用

  # ---- [可选] 属性修改器 ----
  # 由于材质是皮革 (几乎无防御), 你需要手动添加属性。
  # 数值参考: 钻石头盔 = 3 armor + 2 toughness
  AttributeModifiers:
    - attribute: GENERIC_ARMOR
      operation: ADD_NUMBER
      amount: 3
    - attribute: GENERIC_ARMOR_TOUGHNESS
      operation: ADD_NUMBER
      amount: 2

# ============================
# 2. 胸甲
# ============================
ruby_chestplate:
  displayname: "<gradient:#FA7CBB:#F14658>Ruby Chestplate"
  material: LEATHER_CHESTPLATE
  Pack:
    generate_model: true
    parent_model: "item/generated"
    textures:
      - default/armors/ruby_chestplate
      - default/armors/ruby_chestplate
  AttributeModifiers:
    - attribute: GENERIC_ARMOR
      operation: ADD_NUMBER
      amount: 8               # 钻石胸甲 = 8
    - attribute: GENERIC_ARMOR_TOUGHNESS
      operation: ADD_NUMBER
      amount: 2

# ============================
# 3. 护腿
# ============================
ruby_leggings:
  displayname: "<gradient:#FA7CBB:#F14658>Ruby Leggings"
  material: LEATHER_LEGGINGS
  Pack:
    generate_model: true
    parent_model: "item/generated"
    textures:
      - default/armors/ruby_leggings
      - default/armors/ruby_leggings
  AttributeModifiers:
    - attribute: GENERIC_ARMOR
      operation: ADD_NUMBER
      amount: 6               # 钻石护腿 = 6
    - attribute: GENERIC_ARMOR_TOUGHNESS
      operation: ADD_NUMBER
      amount: 2

# ============================
# 4. 靴子
# ============================
ruby_boots:
  displayname: "<gradient:#FA7CBB:#F14658>Ruby Boots"
  material: LEATHER_BOOTS
  Pack:
    generate_model: true
    parent_model: "item/generated"
    textures:
      - default/armors/ruby_boots
      - default/armors/ruby_boots
  AttributeModifiers:
    - attribute: GENERIC_ARMOR
      operation: ADD_NUMBER
      amount: 3               # 钻石靴子 = 3
    - attribute: GENERIC_ARMOR_TOUGHNESS
      operation: ADD_NUMBER
      amount: 2
```

### 使用此模板的步骤

1. **全局替换**: 所有 `ruby` → 你的盔甲名, `Ruby` → 显示名
2. **确认 settings.yml**:
   ```yaml
   CustomArmor:
     armor_type: SHADER
     armor_resolution: 16      # 按需调整
   ```
3. **准备纹理文件** (共 6-8 个):
   - `ruby_armor_layer_1.png` — 64x32 @ 16px, **必须 32 位**
   - `ruby_armor_layer_2.png` — 64x32 @ 16px, **必须 32 位**
   - `ruby_armor_layer_1_e.png` — [可选] 发光贴图
   - `ruby_armor_layer_2_e.png` — [可选] 发光贴图
   - `ruby_helmet.png` — 物品图标
   - `ruby_chestplate.png` — 物品图标
   - `ruby_leggings.png` — 物品图标
   - `ruby_boots.png` — 物品图标
4. **放置纹理**: `~/textures/default/armors/`
5. **重载**: `/o reload all` 或重启服务器
6. **如果使用 Iris**: 安装 CIT Resewn 模组
7. **获取物品**: `/o give <玩家> ruby_helmet`

## 着色器原理

### 原版渲染流程 (简化)

```
皮革盔甲渲染:
  基础纹理 (leather_layer_1/2.png)
    +
  染色叠加层 (由皮革盔甲的 color NBT 决定)
    ↓
  最终像素颜色

Oraxen 着色器注入后:
  基础纹理 (leather_layer_1/2.png)
    +
  自定义着色器拦截检测
    ├→ 如果物品是 Oraxen 自定义盔甲 → 替换为自定义纹理
    └→ 如果是普通皮革盔甲 → 保持原版染色行为
    ↓
  最终像素颜色
```

### 对着色器方法的影响

- **原版 (无模组)**: 着色器正常工作, 自定义纹理显示
- **Optifine**: Optifine 重写着色器 → Oraxen 着色器失效 → Oraxen 自动生成 CIT 文件替代
- **Iris**: Iris 重写着色器 → Oraxen 着色器失效 → 需要 CIT Resewn 读取 CIT 文件

## CIT (Custom Item Texture) 生成

### 什么是 CIT

CIT (Custom Item Texture) 是 Optifine 的特性, 允许基于物品的 NBT 数据、名称、附魔等条件动态切换纹理。

### Oraxen 的自动处理

当 `CustomArmor.armor_type` 设为 `SHADER` 时, Oraxen 会:

1. 检测是否有 Optifine 格式的 CIT 需求
2. 自动为每个自定义盔甲物品生成 `.properties` 文件
3. 将这些 CIT 文件打包进资源包
4. Optifine 用户无需任何额外操作

### 生成的文件示例

Oraxen 自动生成的 CIT 文件位于资源包中, 典型内容如下:

```properties
# 自动生成 — 无需手动创建
type=armor
items=leather_helmet
texture=default/armors/ruby_helmet.png
nbt.display.Name=pattern:Ruby Helmet
```

### Iris 用户额外步骤

由于 Iris 不内置 CIT 支持, 你需要:

1. 安装 [CIT Resewn](https://modrinth.com/mod/cit-resewn) 模组
2. 确保 CIT Resewn 版本与你的 Iris 版本兼容
3. Oraxen 生成的 CIT 文件将由 CIT Resewn 读取

## 可染色能力 (Dyeable)

### 着色器方式的独特优势

着色器方式使用的皮革盔甲基础材质保留了**原版染色功能**。这意味着你可以通过设置物品的 `color` NBT 标签来改变盔甲的颜色。

```yaml
# 示例: 创建一个可染色的自定义头盔
ruby_helmet:
  displayname: "<gradient:#FA7CBB:#F14658>Ruby Helmet"
  material: LEATHER_HELMET
  Pack:
    generate_model: true
    parent_model: "item/generated"
    textures:
      - default/armors/ruby_helmet
      - default/armors/ruby_helmet
  # 如果同时使用染色, 染色会叠加在你的纹理之上
```

### 染色与自定义纹理的交互

| 场景 | 效果 |
|------|------|
| 玩家未染色 (默认) | 显示自定义纹理 |
| 玩家用染料染色 | **自定义纹理会叠加一层颜色滤镜** |
| 用于隐藏的探测性着色 | 可用于创建有基础色但可微调的盔甲 |

### 限制

- 染色无法改变盔甲层纹理 — 只能叠加色调
- 如果自定义纹理颜色很深, 染色效果可能不明显
- 组件方式 (1.21.2+) 通过 `dyeable` 组件也支持染色, 建议升级

## 发光纹理 (_e.png)

### 格式

为盔甲层纹理添加一个同名但以 `_e.png` 结尾的纹理文件:

```
ruby_armor_layer_1.png      → 基础纹理
ruby_armor_layer_1_e.png    → 发光贴图 (emissive map)
ruby_armor_layer_2.png      → 基础纹理
ruby_armor_layer_2_e.png    → 发光贴图
```

### 发光规则

- 像素的**透明度**被解释为**发光强度**
- 完全不透明的像素 = 最大发光
- 完全透明的像素 = 无发光
- 半透明 = 部分发光

### 示例

如果你的红宝石头盔上有发光的符文:
1. 在 `ruby_armor_layer_1.png` 中绘制完整的盔甲纹理
2. 在 `ruby_armor_layer_1_e.png` 中, 只让符文部分的像素不透明, 其余全部透明
3. 符文将在黑暗中发光, 不受环境光照影响

**注意**: 发光纹理**不需要 Optifine 或其他模组**即可在原版客户端上生效。

## 与其他方法的对比

### 着色器方式 vs 组件方式 (1.21.2+)

| 对比点 | 着色器 (1.18-1.19.4) | 组件 (1.21.2+) |
|--------|:--------------------:|:--------------:|
| 基础材质 | LEATHER (皮革) 限定 | **任意** |
| 需要 CIT | **是** (Optifine 自动, Iris 需 CIT Resewn) | **否** |
| 纹理位深要求 | **32位强制** | 无限制 |
| 盔甲防御值 | 手动添加 AttributeModifiers | 直接用对应材质即可 |
| 纹饰支持 | **不支持** | 支持 |
| 热重载 | `/o reload` | `/o reload` |
| 性能 | 一般 (着色器钩子开销) | 最佳 (纯原版机制) |

### 着色器方式 vs 纹饰方式 (1.20-1.21.1)

| 对比点 | 着色器 (1.18-1.19.4) | 纹饰 (1.20-1.21.1) |
|--------|:--------------------:|:------------------:|
| MC 版本覆盖 | 1.18-1.19.4 (及更早) | 1.20-1.21.1 |
| 基础材质 | LEATHER | CHAINMAIL |
| 可染色 | **是** | 否 |
| Optifine 兼容 | 自动 CIT | 原生兼容 |
| Iris 兼容 | 需 CIT Resewn | 原生兼容 |
| 发光纹理 | 支持 | 支持 (取决于纹理) |
| 服务器重启 | 1次 reload | 需要 2 次重启 |

### 何时必须使用着色器方式

- 服务器版本为 1.18-1.19.4, 无法升级
- 需要**可染色**功能 (这是着色器方式在旧版中的独特优势)
- 维护已有的旧版配置, 只需添加新盔甲

## 常见问题

### Q: 穿戴盔甲后身体上显示的是黑色而不是我的纹理!

这是着色器方式最常见的问题。按顺序排查:

1. **纹理位深**: 在图像编辑器中检查是否为 **32 位** PNG。不是 32 位 = 最可能的原因。
2. **纹理命名**: 是否包含 `armor_layer_1` 或 `armor_layer_2`
3. **settings.yml**: `armor_type` 是否为 `SHADER`
4. **文本放置路径**: 是否在资源包纹理文件夹中

### Q: Optifine 用户能看到盔甲, 但原版用户看到的是黑色?

确认你的盔甲层纹理是 **32 位** PNG。Optifine 对位深要求较宽松 (它会走 CIT 路径), 但原版渲染严格要求 32 位。

### Q: Iris 用户看不到盔甲纹理?

确认已安装 [CIT Resewn](https://modrinth.com/mod/cit-resewn) 模组。Iris 自身不支持 CIT, 而 Oraxen 的着色器方式在 Iris 下依赖 CIT 文件。

### Q: 可以同时使用着色器和纹饰/组件方式吗?

技术上是可能的, 但会导致混乱:
- `settings.yml` 中 `armor_type` 是全局设置, 设为 `SHADER` 后所有自动推断都按着色器逻辑来
- 如果你在 1.21.2+ 服务器上, 直接全部使用组件方式
- 如果必须混用, 可以为不同盔甲手动指定完整配置, 但不推荐

### Q: 如何给着色器盔甲添加防御值?

所有着色器方式的盔甲都是皮革材质 (近乎 0 防御), 必须手动添加:

```yaml
AttributeModifiers:
  - attribute: GENERIC_ARMOR
    operation: ADD_NUMBER
    amount: 3              # 盔甲值 (参考: 皮革=1, 锁链=2, 铁=2, 钻石=3)
  - attribute: GENERIC_ARMOR_TOUGHNESS
    operation: ADD_NUMBER
    amount: 0              # 盔甲韧性 (参考: 钻石=2, 下界合金=3)
  - attribute: GENERIC_KNOCKBACK_RESISTANCE
    operation: ADD_NUMBER
    amount: 0              # 击退抗性 (只有下界合金有)
```

### Q: 颜色染色会覆盖我的自定义纹理吗?

不会完全覆盖。染色会产生一个颜色滤镜, 叠加在你的纹理之上。纹理的原始颜色仍然可见, 但会偏向染色的色调。

如果你不希望玩家染色, 可以在 Oraxen 的物品配置中移除染色交互支持, 或者不给玩家发放染料。
