# 家具存储配置模板

> Oraxen 家具存储机制允许你创建自定义存储容器 —— 箱子、衣柜、保险箱、垃圾桶等。
> 共有 4 种存储类型，每种用途不同。

---

## 重要前提

> **家具存储需要启用屏障（barrier）才能工作。** 玩家通过右键点击屏障方块来打开存储界面。
> 如果使用 `hitbox`（展示实体），也可以右键碰撞箱区域来打开。

---

## 一、存储类型概述

| 类型 | 描述 | 适用场景 |
|------|------|----------|
| `STORAGE` | 共享容器 —— 所有玩家看到的物品栏内容相同 | 公共箱子、社区储藏室 |
| `PERSONAL` | 个人容器 —— 每个玩家看到自己独立的物品栏 | 个人保险箱、衣柜 |
| `ENDERCHEST` | 末影箱 —— 直接访问该玩家的原版末影箱 | 末影箱访问终端 |
| `DISPOSAL` | 垃圾桶 —— 关闭界面时自动删除所有放入的物品 | 垃圾箱、物品销毁器 |

---

## 二、STORAGE —— 共享容器

> 类似普通箱子。任何玩家都可以打开并查看/取走其中的物品。

```yaml
# ============================================================
# 示例: 公共储物箱
# ============================================================
public_chest:
  displayname: "<yellow>公共储物箱</yellow>"
  material: PAPER
  Pack:
    generate_model: false
    model: default/public_chest
  Mechanics:
    furniture:
      type: DISPLAY_ENTITY
      barrier: true                       # 存储功能需要屏障

      storage:
        type: STORAGE                     # 共享容器
        rows: 6                           # 行数 (1-6, 默认 6)
        title: "<red>公共仓库</red>"       # 容器标题 (支持 MiniMessage)
        open_sound: block.chest.open      # 打开音效 (默认)
        close_sound: block.chest.close    # 关闭音效 (默认)
```

---

## 三、PERSONAL —— 个人容器

> 类似自定义末影箱。每个玩家在这个家具中看到**自己独立的物品栏**。
> 用于制作个人保险箱、衣柜等私人存储。

```yaml
# ============================================================
# 示例: 个人保险箱
# ============================================================
personal_safe:
  displayname: "<gold>个人保险箱</gold>"
  material: PAPER
  Pack:
    generate_model: false
    model: default/personal_safe
  Mechanics:
    furniture:
      type: DISPLAY_ENTITY
      barrier: true

      storage:
        type: PERSONAL                    # 个人容器（每人独立物品栏）
        rows: 5                           # 行数 (1-6)
        title: "<green>%player_name% 的保险箱</green>"
        open_sound: entity.shulker.open   # 打开音效（末影箱风格）
        close_sound: entity.shulker.close # 关闭音效
```

### PERSONAL 类型说明

- 每个玩家的物品栏**完全独立**，互相看不到对方的物品
- 行数可自定义（1-6），不受原版末影箱 3 行限制
- 服务器重启后物品**不会丢失**（保存在插件数据中）
- 支持 PlaceholderAPI（如 `%player_name%`）显示玩家名

---

## 四、ENDERCHEST —— 末影箱访问

> 打开该家具时，直接显示**该玩家的原版末影箱物品栏**。
> 物品保存在玩家的末影箱数据中，与其他地方打开末影箱内容一致。

```yaml
# ============================================================
# 示例: 末影箱访问终端
# ============================================================
ender_terminal:
  displayname: "<dark_purple>末影终端</dark_purple>"
  material: PAPER
  Pack:
    generate_model: false
    model: default/ender_terminal
  Mechanics:
    furniture:
      type: DISPLAY_ENTITY
      barrier: true

      storage:
        type: ENDERCHEST                  # 直接访问原版末影箱
        title: "<light_purple>末影箱</light_purple>"
        open_sound: block.ender_chest.open
        close_sound: block.ender_chest.close
```

### ENDERCHEST 类型说明

- 行数固定为 3（受原版末影箱限制，不可自定义）
- **不需要**设置 `rows` 字段
- 物品保存在玩家的末影箱 NBT 数据中

---

## 五、DISPOSAL —— 垃圾桶

> 玩家将不需要的物品放入，关闭 GUI 时所有物品被**永久删除**。
> 没有确认对话框 —— 物品一旦放入并关闭就会消失。

```yaml
# ============================================================
# 示例: 垃圾桶
# ============================================================
trash_can:
  displayname: "<dark_gray>垃圾桶</dark_gray>"
  material: PAPER
  Pack:
    generate_model: false
    model: default/trash_can
  Mechanics:
    furniture:
      type: DISPLAY_ENTITY
      barrier: true

      storage:
        type: DISPOSAL                    # 垃圾桶（关闭时删除物品）
        rows: 3                           # 行数 (1-6)
        title: "<red>垃圾桶 - 关闭后物品将永久消失!</red>"
        open_sound: entity.item_frame.remove_item
        close_sound: entity.generic.extinguish_fire
```

### DISPOSAL 类型说明

- **没有恢复机制** —— 物品关闭时立即删除
- 建议在 `title` 中明确警告玩家
- 服务器重启时容器内的物品**不会保存**

## 六、存储选项汇总

### 6.1 完整选项表

```yaml
Mechanics:
  furniture:
    barrier: true                         # 必填! 存储功能依赖屏障
    storage:
      type: STORAGE                       # STORAGE / PERSONAL / ENDERCHEST / DISPOSAL
      rows: 6                             # 行数 (1-6)，ENDERCHEST 不可设置
      title: "<red>容器标题</red>"         # GUI 标题，支持 MiniMessage
      open_sound: block.chest.open        # 打开时播放的音效
      close_sound: block.chest.close      # 关闭时播放的音效
```

### 6.2 各类型默认值

| 配置项 | STORAGE | PERSONAL | ENDERCHEST | DISPOSAL |
|--------|---------|----------|------------|----------|
| `rows` 默认值 | `6` | `6` | `3`(固定) | `6` |
| `title` 默认值 | `"Storage"` | `"Storage"` | (末影箱) | `"Storage"` |
| `open_sound` 默认值 | `entity.chest.open` | `entity.chest.open` | - | `entity.chest.open` |
| `close_sound` 默认值 | `entity.chest.close` | `entity.chest.close` | - | `entity.chest.close` |
| `rows` 可自定义 | 是 | 是 | 否 | 是 |
| 物品持久化 | 是 | 是 | 是(原版) | 否 |

## 七、常用音效参考

| 音效 ID | 描述 |
|--------|------|
| `block.chest.open` | 箱子打开 |
| `block.chest.close` | 箱子关闭 |
| `block.ender_chest.open` | 末影箱打开 |
| `block.ender_chest.close` | 末影箱关闭 |
| `entity.shulker.open` | 潜影盒打开 |
| `entity.shulker.close` | 潜影盒关闭 |
| `block.barrel.open` | 木桶打开 |
| `block.barrel.close` | 木桶关闭 |
| `entity.item_frame.remove_item` | 物品展示框取下物品 |
| `entity.generic.extinguish_fire` | 灭火 |

## 八、完整示例收集

### 8.1 带 BlockLocker 保护的公共仓库

```yaml
protected_warehouse:
  displayname: "<blue>受保护的仓库</blue>"
  material: PAPER
  Pack:
    generate_model: false
    model: default/warehouse
  Mechanics:
    furniture:
      type: DISPLAY_ENTITY
      barrier: true
      blocklocker:
        can_protect: true
        protection_type: CONTAINER
      storage:
        type: STORAGE
        rows: 6
        title: "<blue>社区仓库</blue>"
      drop:
        silktouch: true
        loots:
          - oraxen_item: protected_warehouse
            probability: 1.0
```

## 九、与音符盒方块存储的对比

> 存储机制同样适用于音符盒（NoteBlock）自定义方块。配置结构一致：

```yaml
# 音符盒方块存储（对比参考）
Mechanics:
  noteblock:
    custom_variation: 10
    model: my_storage_block
    storage:
      type: STORAGE
      rows: 5
      title: "<red>方块存储</red>"
```

> 主要区别：音符盒方块不需要 `barrier: true`，因为是方块本身提供碰撞。

## 十、常见问题

**Q: 玩家破坏存储家具后，里面的物品会怎样？**
A:
- `STORAGE`: 物品**丢失**（破坏时不掉落内容物）
- `PERSONAL`: 物品保存在插件数据中，重新放置后恢复
- `ENDERCHEST`: 物品在末影箱中，不受影响
- `DISPOSAL`: 物品在关闭时已删除

**Q: 如何让存储家具在精准采集破坏时不删除内容物？**
A: 配置 `drop.silktouch: true` 即可 —— 仅精准采集时掉落家具，物品保留。

**Q: 可以不使用屏障而使用 hitbox 吗？**
A: 可以。使用 `hitbox`（展示实体）定义碰撞区域，玩家右键该区域即可打开存储界面。但仍建议保留屏障以确保可靠性。
